# Person email endpoints

Live contract: `GET https://api.kingminos.com/openapi.yaml` (also `/openapi.json`). REST and hosted MCP (`https://mcp.kingminos.com`) share the Bearer tool inventory. Trimmed copy of the pack map (`api` skill `references/endpoints.md`); `npm run validate` keeps these rows matching it.

## REST ↔ tools

| REST | Tool id (OpenAPI operationId) | Access | Owner / notes |
| --- | --- | --- | --- |
| `POST /v1/person/email` | `person_email` | R | A person's verified work email (`person.email`). Send `first_name` + `last_name` + `company_domain` (name route; `domain` alias) and/or `linkedin_url` (LinkedIn route), top level or under `person`; a name without a domain, or a domain without a name and no `linkedin_url` → `400 validation_failed` / `insufficient_input` (also `invalid_linkedin_url` \| `invalid_domain`). No guessed patterns: only vendor-verified addresses are delivered. `answer.outcome` / `result.status` `found` \| `not_found` \| `conflict` (two different addresses) \| `catch_all` (domain accepts every address; withheld); `reason_code` `zero_hits` \| `person_mismatch` \| `sources_disagree` \| `below_min_confidence` \| `compliance_blocked` \| `provider_error` …. `result.email` (`found` only), `result.email_status` (`valid` on `found`), `result.route` (`name` \| `linkedin`), `result.confidence` (two independent sources agreeing `high`, one `medium`), `result.flags` (`single_source` \| `verified_by_second_vendor` \| `finders_agree` \| `person_mismatch` \| `domain_mismatch` \| `personal_mailbox`), `result.candidates[]` (addresses only on `found`), `result.person`. A wrong person, an address on another domain, or a personal mailbox is dropped. `routing.path` `speed` \| `balance` (default; adds an independent mailbox check) \| `accuracy` \| `coverage` (adds the LinkedIn route) — outcome-priced 1.5–5 credits on a delivered email, 0 on a miss, `conflict`, `catch_all` or withhold; BYOK 0.1; `routing.only` / `ignore` honored. Confidence is the only write signal: default floors speed / coverage `low`, balance `medium`, accuracy `high`; `min_confidence` overrides. 30-day hits-only cache (`skip_cache` / `X-Router-Cache: bypass`; replay 0 credits). `451 subject_suppressed` on a suppressed `linkedin_url` (0 credits); a suppressed found address is withheld (`compliance_blocked`). API tenants only. → `person-email`. |
| `POST /v1/email/verify` | `email_verify` | R | Is this mailbox deliverable? (`email.verify`). `email` required (≤ 320 chars; `400 validation_failed` / `email_required` \| `email_too_long`); a malformed address is answered, not rejected. `answer.outcome` / `result.status` `valid` \| `invalid` \| `catch_all` \| `unknown`. Free local checks first (syntax, reserved domain, no such domain, no mail host → `invalid`, `result.source: local`, 0 credits), then vendor checks (`source: vendor`). `result.confidence` (two agreeing checks `high`, one `medium`, conflicting `low` → `unknown` + `vendor_disagreement`), `result.flags` (`role_based` \| `free_mailbox` \| `disposable` \| `relay` \| `security_gateway` \| `vendor_disagreement`; describe the mailbox, never change the status), `result.mx_provider`, `result.checked_at`, `result.candidates[]` (verdict per check; never a name or employer). `routing.path` `speed` \| `balance` (default) \| `accuracy` (both checks must agree) \| `coverage` (one conclusive check is enough) — outcome-priced 0.5–1.5 credits on a delivered vendor `valid` / `invalid`; `catch_all`, `unknown`, local `invalid`, withhold and timeout bill 0; BYOK 0.1; `routing.only` / `ignore` honored. Default floors speed / coverage `low`, balance `medium`, accuracy `high`; `min_confidence` overrides (below the floor → `unknown`, `below_min_confidence`). Not cached. `451 subject_suppressed` at 0 credits. API tenants only. → `email-verify`. |
